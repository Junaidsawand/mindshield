# Chapter 6 — Machine Learning Model Development & Baselines

This chapter describes the formulation, design, training pipeline, and comparative benchmarking of MindShield's machine learning model development. It details the fine-tuning of the deep-learning sequence classifier and benchmarks its performance against classical machine learning baselines under controlled evaluation environments.

---

## 6.1 Introduction

The primary objective of MindShield's machine learning module is to determine whether an incoming SMS message contains threat indicators (representing spam or phishing vectors) or is benign. 

The classification task is modeled as a supervised binary sequence classification problem. Incoming SMS inputs are mapped to one of two target labels:
* **`0` (Ham):** Benign messages, including personal conversations, carrier subscription alerts, and legitimate transactional receipts.
* **`1` (Spam):** Malicious or unsolicited messages, including smishing links, OTP theft requests, and lottery/financial scams.

### Table 6.1 — ML Problem Definition

| Task Type | Input Representation ($x$) | Output Label ($y$) | Target Domain |
| :--- | :--- | :--- | :--- |
| **Supervised Binary Classification** | Text string (Tokenized WordPiece sequence) | $\{0, 1\}$ | $0 \rightarrow$ Ham (Legitimate)<br>$1 \rightarrow$ Spam (Threat) |

At the machine learning model layer, the pipeline is strictly binary. Specific threat categorization labels (such as `prizeScam`, `phishing`, or `investmentFraud`) are not generated by the ML classifier; instead, they are mapped downstream via **rule-based attack-vector categorization** on the server.

## 6.2 Machine Learning Problem Formulation

Let $x$ represent the raw input sequence of characters in the SMS message body. The tokenizer transforms $x$ into a sequence of $N$ subword token IDs:

$$\mathbf{w} = [w_{\text{[CLS]}}, w_1, w_2, \dots, w_K, w_{\text{[SEP]}}, w_{\text{[PAD]}}, \dots]$$

where $K$ is the length of the parsed text tokens, subject to a sequence length limit $L$ ($K \le L - 2$).

The token sequence is passed to the transformer encoder, which outputs a contextual embedding vector $\mathbf{h}_{\text{[CLS]}} \in \mathbb{R}^D$ representing the aggregate classification token.

The binary sequence classification head applies a linear transformation to map $\mathbf{h}_{\text{[CLS]}}$ to raw logits $\mathbf{z} = [z_0, z_1] \in \mathbb{R}^2$:

$$\mathbf{z} = \mathbf{W} \mathbf{h}_{\text{[CLS]}} + \mathbf{b}$$

where $\mathbf{W} \in \mathbb{R}^{2 \times D}$ and $\mathbf{b} \in \mathbb{R}^2$ represent the trainable weights and biases of the classification linear layer.

The logits are transformed into class probability distributions using the Softmax function:

$$\hat{y}_c = \sigma(\mathbf{z})_c = \frac{e^{z_c}}{\sum_{j=0}^{1} e^{z_j}} \quad \text{for } c \in \{0, 1\}$$

The predicted label is determined by selecting the class with the maximum probability:

$$\hat{y} = \arg\max_{c \in \{0,1\}} (\hat{y}_c)$$

The confidence score $C$ exposed to the system represents the probability of the predicted class:

$$C = \max(\hat{y}_0, \hat{y}_1)$$

If $\hat{y} = 1$ (Spam) and $C \ge \theta$ (where $\theta$ is the classification threshold, set to $0.70$ in client configurations), the system flags the message as a threat.

## 6.3 Model Development Strategy

MindShield's model development progressed through three main stages to address domain generalization:

1. **Baseline Evaluation (UCI):** Training a classifier on the cleaned international UCI SMS Spam dataset.
2. **Domain-Shift Discovery:** Evaluating the base model against legitimate local Pakistani transactions, which revealed a massive generalization failure (False Positive Rate of 93.1%).
3. **Localized Fine-Tuning:** Developing successive versions of the `PakScam-SMS` dataset (`v1` to `v3`) to adapt the model to bilingual and local transaction structures while maintaining performance on baseline English datasets.

## 6.4 DistilBERT Architecture

MindShield uses **DistilBERT** (`distilbert-base-uncased`), an encoder-only transformer model trained using knowledge distillation from the larger BERT architecture.

```
Input Tokens: [CLS] -> "Check" -> "your" -> "OTP" -> [SEP]
  │
  ▼ (Embedding Layer)
Word & Position Representations
  │
  ▼ (6 Multi-Head Self-Attention Layers)
Contextual Feature Vectors
  │
  ▼
Output Hidden State for [CLS] Token (h_[CLS])
  │
  ▼ (Linear Classification Head)
Logits: [z_0, z_1] ──► (Softmax) ──► Class Probabilities [y_0, y_1]
```

### Key Architectural Invariants:
* **Distillation Mechanics:** Developed by compressing the BERT model by 40% while preserving 97% of its language understanding capabilities and increasing speed by 60%.
* **Layers:** Uses 6 transformer layers (compared to 12 in BERT-base).
* **Dimensions:** Hidden dimension size $D = 768$, with 12 attention heads.
* **Embeddings:** Positional information is injected using absolute learned position embeddings, allowing parallel self-attention computation over inputs.

## 6.5 Why DistilBERT

MindShield selected DistilBERT for sequence classification based on key technical trade-offs:

1. **Contextual Token Representations:** Unlike bag-of-words classical baselines, DistilBERT models word order and syntax. This allows it to capture the contextual difference between `"Check your transaction OTP"` (benign alert) and `"Share your OTP immediately to avoid account block"` (phishing threat).
2. **Computational Speed:** Since SMS messages are short (under 2,000 characters), DistilBERT's reduced layer count (6 layers) provides fast inference times (~57ms on CPU) suitable for near-instant client alerts.
3. **Deployment Feasibility:** DistilBERT's parameter size (~66M parameters, 255MB) fits within lightweight backend deployment models, preventing high hosting and resource overhead.

## 6.6 Tokenization and Model Input

The text preprocessing pipeline feeds SMS strings into the HuggingFace `AutoTokenizer` composition root:

1. **WordPiece Parsing:** Breaks tokens down into subwords. Unseen local words (e.g., Urdu or Roman Urdu terms) are split into common roots (e.g., `"ibft"` -> `["i", "##b", "##ft"]`).
2. **Batch Construction:** 
   - Tensors are constructed using token IDs (`input_ids`) and attention masks (`attention_mask`).
   - Training sequences are padded/truncated to a static maximum sequence length of **64 tokens** to optimize memory. Inference sequences support up to **128 tokens**.

## 6.8 Loss Function

The training loop optimizes model weights using the **Binary Cross-Entropy (BCE) Loss** computed on the final classification output:

$$\mathcal{L} = -\frac{1}{M} \sum_{i=1}^{M} \left[ y_i \log(\hat{y}_i) + (1 - y_i) \log(1 - \hat{y}_i) \right]$$

where $M$ is the batch size, $y_i$ is the true binary label ($0$ or $1$), and $\hat{y}_i$ is the Softmax probability score predicted for the spam class.

## 6.9 Classical Machine Learning Baselines

To establish model efficiency benchmarks, MindShield evaluated eight classical machine learning pipelines. The best-performing baseline was `linear_svm_count`:

* **Feature Vectorizer:** `CountVectorizer` (tokenizes text and builds term frequency count vectors; TF-IDF was evaluated but yielded lower F1-scores).
* **Classifier:** Linear Support Vector Machine (`linear_svm`).
* **SVM Optimization:** Finds the optimal separating hyperplane that maximizes the margin between classes:
  $$\min_{\mathbf{w}, b} \frac{1}{2} \|\mathbf{w}\|^2 + C \sum_{i=1}^{M} \xi_i$$
  subject to $y_i (\mathbf{w}^T \mathbf{x}_i + b) \ge 1 - \xi_i$ and $\xi_i \ge 0$.

## 6.11 The SVM Winner Paradox

An analysis of the benchmark results reveals the **SVM Winner Paradox**: the simple, classical Linear SVM model outperforms the deep-learning DistilBERT model across almost all in-domain metrics, while being $1,300\times$ smaller in size and $10\times$ faster in inference.

### Why does SVM perform better on the in-domain test split?
The UCI dataset contains clear, keyword-heavy separations between spam and ham. A linear classifier combined with count vectorization easily memorizes these sparse token correlations (e.g., "win," "claim," "call" are strongly associated with spam), achieving near-perfect scores.

### Why DistilBERT remains critical:
While SVM excels at local token matching, it lacks semantic context. If a phishing message is written with benign vocabulary or structural changes, the SVM cannot generalize. DistilBERT, by utilizing multi-head self-attention, learns contextual patterns, which is critical for identifying local smishing variants (as detailed in the domain generalization experiments in Chapter 7).

## 6.13 Evaluation Methodology

Model performance is measured using standard statistical classification metrics:

* **Accuracy:** Overall proportion of correct predictions.
* **Precision (Positive Predictive Value):** Of all predicted threat alerts, how many were true threats?
  $$\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}}$$
* **Recall (Sensitivity):** Of all true threats in the dataset, how many did the system catch?
  $$\text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}}$$
* **F1-Score:** The harmonic mean of precision and recall.
* **ROC-AUC:** Area under the Receiver Operating Characteristic curve.

In MindShield, **Precision is the highest priority metric**. A false negative (missing a spam message) leaves spam in the inbox; a false positive (blocking a banking OTP or transaction receipt) can disrupt critical user services.

## 6.14 Error Analysis

A review of baseline classification outputs highlights clear error vectors:

* **False Positives (Base Model):** Legitimate banking notifications (e.g., UBL receipts) containing transactional indicators are flagged as phishing because the model associates the terms `"ATM"`, `"debit"`, and URL links with scams.
* **False Negatives:** Cryptic or short smishing messages containing obfuscated links that do not match standard WordPiece vocab terms.

## 6.16 Model Selection Discussion

The trade-offs between SVM and DistilBERT are summarized as follows:

1. **Resource Efficiency:** SVM is highly lightweight, making it suitable for low-power edge nodes.
2. **Semantic Capability:** DistilBERT captures sentence structure and word order, which is necessary to classify complex, bilingual, and Roman Urdu smishing threats.
3. **Verdict:** DistilBERT was selected for the core analysis engine due to its generalization potential, while the fast heuristic engine acts as an immediate fallback layer.

---

## 6.17 Limitations of the ML Approach

* **Remote Inference Requirement:** The 255MB DistilBERT model requires hosting on a remote server, making SMS analysis dependent on network connectivity.
* **Cold-Start Latency:** Model initialization and CPU weight loading take up to 2-3 seconds during server startup.
* **Urdu Generalization Limits:** Pre-trained models have minimal Roman Urdu representations, requiring custom fine-tuning data to prevent high false alarm rates.
