# Database Schema Audit

This document describes the structure, table schemas, and migration paths of MindShield's local SQLite storage database (`mindshield.db`).

---

## 1. Local SQLite Database Configuration

* **File Name:** `mindshield.db`
* **Default Directory:** Native app application documents directory (`/data/data/com.mindshield.mindshield/databases/` on Android).
* **Current Schema Version:** 2

---

## 2. Table Schema: `sms_messages`

The database contains a single centralized table `sms_messages` that stores intercepted SMS records and their associated analysis outputs:

| Column Name | SQLite Data Type | Key Constraints | Default Value | Description / Scope |
| :--- | :--- | :--- | :--- | :--- |
| **`id`** | TEXT | PRIMARY KEY | — | Unique message UUID generated by Android or Dart. |
| **`sender`** | TEXT | NOT NULL | — | Raw sender phone number or alphanumeric shortcode. |
| **`body`** | TEXT | NOT NULL | — | Raw body content of the intercepted SMS message. |
| **`timestamp`** | INTEGER | NOT NULL | — | Epoch millisecond timestamp of receipt. |
| **`ai_status`** | TEXT | NOT NULL | — | Classification status: `'pending'`, `'safe'`, `'suspicious'`, or `'scam'`. |
| **`is_read`** | INTEGER | NOT NULL | 0 | 0 = Unread, 1 = Read (used for UI badge counts). |
| **`confidence_score`**| REAL | NULLABLE | — | Model classification probability score in [0.0, 1.0]. |
| **`detected_threats`** | TEXT | NOT NULL | '[]' | JSON-encoded string list of detected indicator features. |
| **`is_spam`** | INTEGER | NOT NULL | 0 | Binary flag: 0 = Benign/Safe, 1 = Quarantine. |
| **`spam_risk_level`** | TEXT | NULLABLE | — | Normalized risk severity: `safe`, `suspicious`, `dangerous`. |
| **`spam_attack_type`**| TEXT | NULLABLE | — | Attack label: `phishing`, `prizeScam`, `investmentFraud`, etc. |
| **`spam_status`** | TEXT | NULLABLE | — | Mitigation state of the spam message. |
| **`quarantined_at`** | INTEGER | NULLABLE | — | Epoch millisecond timestamp of quarantine execution. |

---

## 3. Database Migrations (v1 $\rightarrow$ v2)

* **Trigger:** Upgrading the DB schema version from 1 to 2.
* **Objective:** Remove the hardcoded dummy inbox and history records (`msg_001` through `msg_012`) seeded in earlier prototype builds to ensure the production application displays only genuine intercepted messages.
* **Migration Script (Executed in Flutter):**
  ```dart
  // Inside database_helper.dart
  Future<void> _upgradeDB(Database db, int oldVersion, int newVersion) async {
    if (oldVersion < 2) {
      final List<String> seedIds = List.generate(12, (index) => 'msg_${(index + 1).toString().padLeft(3, '0')}');
      
      final deleteCount = await db.delete(
        'sms_messages',
        where: 'id LIKE "msg_0%" AND id IN (${List.filled(seedIds.length, '?').join(', ')})',
        whereArgs: seedIds,
      );
      debugPrint('Database migration: Deleted $deleteCount seed mock messages during v1 -> v2 upgrade.');
    }
  }
  ```
* **Security & Privacy Invariant:** The database does not perform automated retention cleaning or deletion of legitimate user SMS. All data remains saved locally on the device until deleted by the user or the application is uninstalled.
